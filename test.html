/* Ticket details reviewed Asset code correct Variable code append(s) added to each applicable link (has http or https) in generated.html Title tag uses token min-width matches (check build width in browser) Layout (matches design file - colors, spacing, image scaling, etc.) Formatting (bolding, italics, superscripts, link styling, etc.) Text compare All links accounted for (href can be #placeholder) Alt text (matches LM, check coloring) Ghost-links (no extra space is linking) Spell check content Verify test results passed (HTML, images, link, spam) EOA testing (see Preview tab) DPI scaling (HTML tag updated, conditionals added) Live testing (iPhone, Android, Gmail desktop) Update the min-width to {{build.breakpoints.large.value}}{{build.breakpoints.large.unit}} Update the width on the "main-table" to width="{{build.breakpoints.large.value}}" style="width:{{build.breakpoints.large.value}}{{build.breakpoints.large.unit}};" Unsubscribe token is correct Preview mobile images off Copyright year hardcoded (except for GNE clients) (IF APPLICABLE) Button clickability (non-standard buttons only) (IF APPLICABLE) Preheader (See config tab, check if variable exists in HTML) (IF APPLICABLE) If VML button, ensure the appropriate link append token exists in the source.html (IF APPLICABLE) Address hack on dark bgs in footer */ **Initial Build: Global** **Ticket details reviewed** Open the ticket. Read all notes inside. Download and look at the dev package. Basically, take a good look around. **Asset code correct** The asset code in the Monday ticket and the Mailflow build should match. **Variable code append(s) added to each applicable link (has http or https) in email.html** The ticket will tell you what the code append should be. AEM is usually c=<%= message.delivery.tacticCode %> VAE will look something like c=abc-123etc. If it says "TBD," skip this step. (It’ll be added later.) Third-party emails have no code appends. To find where it’s listed: Mailflow: Go to the Config tab of the email GitHub: It’s in the frontmatter (the top area between the dashes) Check the email.html file. The link append should be added to every https/http link in the generated.html. **Title tag uses token** This is in between the tags near the top of the HTML. Does the title tag in the Config tab match what’s in the Monday ticket? Is the {{build.title}} token used? If you’re in GitHub, there are no tokens, so it should just have the Monday content in the title tag. **Min-width matches** Did you see the min-width in the global styles? It should also be in the HTML on the main-table class. These should match, using the tokens {{build.breakpoints.large.value}}{{build.breakpoints.large.unit}}. Use Inspect Element to confirm that it really is the set width. Preview the email. Go to the “Fluid” option so there are no width restrictions. Inspect element to confirm that it isn’t wider than it should be. **Layout (matches design file - colors, spacing, image scaling, etc.)** This is a lot of looking at stuff. Line up the build next to the handoff file and compare. We should be accurate within about 5px. Our rule is that line height is usually the font size + 4, so things may not line up there. In that case, measure the gaps on top and bottom. **Formatting (bolding, italics, superscripts, link styling, etc.)** This one is also looking at stuff. Pay extra attention to the references section, if existing, because there’s often italics. Tip: Search for the ® symbol and see if it isn’t superscripted anywhere it’s supposed to be superscripted. You can also keep an eye on this as you text compare. **Text compare** If you have an XD file that only lets you select one tiny paragraph at a time, use this work-around: Go to Finder and find the PDF. Right-click the PDF. Open With > Preview. (It’s most of the way down on the list.) Compare the text, keeping an eye out for multi-column layouts, which it doesn’t always handle well. Text compare with Meltmail Builder. There are a few differences that are OK: Bullets in bulleted lists might have extra spaces between them and the list item text. It just does that. Smart double quotes (“”) break in Outlook, so we swap in plain quotes. **All links accounted for (href can be #placeholder)** We sometimes do that for smart single quotes (‘’) too, just to match. Secret invisible symbols may have been in the PSD/XD file. We delete those when we see them, so they should be missing from our text. Look at each link listed in the link matrix (aka ERB, linked in the Monday ticket). Does it show up as a link in the build? Are any links missing? We sometimes put in #placeholder for the href and that’s fine. The tag just needs to exist. **Alt text (matches LM, check coloring)** You have 2 things to check in here. Go to the ERB/link matrix spreadsheet and scroll down to see the alt text. It should match. Mailflow: You can check this in the Config tab or in the email.html Using Command + F instead of eyeballing is the best way to ensure a match. Check that the alt text is in readable colors. There are several ways to do this. One way is to preview the email and disable the images. Look for any problems, such as dark alt text on a dark background. ** Ghost-links (no extra space is linking) ** A “ghost link” is a class that goes on an image link so that the empty area on either side of the image doesn’t turn into a link too. There are 2 ways to check this. Pick your favorite: Hover over each image in the build and move your mouse from side to side. Does the link extend beyond the image or is it the same size? Search src=" and check each image. If there's an tag around it, then the tag (not the image) should have the ghost-link class on it. But there are exceptions: The image is just as wide as the build, so there’s no empty space to get linked (e.g. header image) The image is tightly contained in a fixed-width td (e.g. 200px image in a 200px td) so there is no blank space to link A ghost link creates ~5px of empty padding below an image, so we may skip the ghost-link class if that would be a bad thing. **Spell check content** Paste the whole content into Visual Studio. (Mailflow doesn’t have spell checking.) Check the scrollbar for blue errors and check each one out. I recommend adding correct spellings of brand names to your dictionary (right-click on them) to stop them from getting flagged.
